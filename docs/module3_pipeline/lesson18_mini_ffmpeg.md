# 第18节：阶段项目一：mini_ffmpeg

## 本节能力目标
- **模块整合能力**：将解封装、解码、滤镜、编码、重采样、封装等零散知识点串联成一个完整的处理管道。
- **工程化思维**：学习如何通过模块化（多文件）组织一个 C++ 音视频工程。
- **命令行设计**：掌握子命令分发逻辑、参数解析以及统一的日志与错误处理。
- **自主实现**：在提供的代码骨架基础上，独立补全核心 FFmpeg API 调用逻辑。

## 真实工程对应场景
- **媒体处理后端**：类似于腾讯云/阿里云的媒体处理服务，底层通常也是将各种能力封装成原子模块进行调用。
- **定制化转码工具**：当通用工具（如 ffmpeg CLI）无法满足特定的业务逻辑（如特殊的加密、私有协议、复杂的动态滤镜）时，需要自研处理工具。

## 引言
恭喜你完成了模块三的学习！在前面的课程中，我们分别攻克了解封装（Demuxing）、解码（Decoding）、滤镜（Filtering）、编码（Encoding）以及重采样（Resampling）等核心环节。

本节课是模块三的结课项目。我们将实现一个名为 `mini_ffmpeg` 的命令行工具，它虽然体积小，但功能涵盖了媒体处理最核心的四个场景：
1. **probe**: 探测并展示媒体流信息。
2. **remux**: 实现高速转封装（Stream Copy）。
3. **transcode**: 实现视频转码并支持画面缩放。
4. **resample**: 实现音频格式、采样率和声道的转换。

## 理论讲解

### 1. 模块化工程结构
为了让代码易于维护，我们将不同功能的子命令拆分到不同的文件中：
- `main.cpp`: 程序的入口，负责分发命令。
- `cmd_probe.cpp`: 对应 `probe` 子命令。
- `cmd_remux.cpp`: 对应 `remux` 子命令。
- `cmd_transcode.cpp`: 对应 `transcode` 子命令。
- `cmd_resample.cpp`: 对应 `resample` 子命令。
- `common.h`: 定义全局通用的工具函数、宏以及跨模块传递的上下文。

### 2. 管道整合的难点
- **时间基换算**：在转码和转封装过程中，输入流和输出流的时间基（`time_base`）往往不同，必须使用 `av_rescale_q` 进行精准转换。
- **状态同步**：解码器、编码器和滤镜容器之间的数据流转，需要严格遵循“发送包 -> 接收帧 -> 发送帧 -> 接收包”的循环。
- **资源释放**：一个完整的管道涉及数十个上下文和缓冲区，必须确保在任何环节出错时，都能通过统一的清理逻辑（如 `goto end;`）释放资源。
- **Flush (刷新) 机制**：解码器、编码器和滤镜图内部通常有缓冲区。当读取完输入文件的所有 Packet 后，必须向管道发送 `NULL` 数据来“挤出”最后几帧，否则输出文件会缺失结尾。

## 关键点总结
- **解封装 -> 解码 -> 滤镜 -> 编码 -> 封装** 是音视频处理的通用模板。
- **模块化** 是复杂音视频工程的基石。
- **严谨的错误处理** 是 C++ 工程质量的保证。

## 预期结果与验收标准

### 预期输出
- `probe`: 控制台打印出清晰的流信息列表。
- `remux`: 生成一个新的容器格式文件，且视频画质无损。
- `transcode`: 生成一个指定分辨率的视频文件。
- `resample`: 生成一个指定采样率/声道的音频文件。

### 验收标准
- 四个子命令均能正确执行。
- 处理过程中无明显的 CPU 异常波动。
- 使用 ASAN 检查通过，无内存泄漏。

## 常见错误与排查
- **参数解析失败**：检查 `main.cpp` 中的 `argc` 判断和字符串匹配。
- **输出文件打不开**：检查 `avformat_write_header` 是否被调用，以及最后是否调用了 `av_write_trailer`。
- **缩放效果无效**：检查 `libavfilter` 的滤镜描述符（`scale=w:h`）是否正确。

## 课后小挑战
1. **添加进度条**：在处理循环中，根据 `pts` 和总时长计算百分比并打印。
2. **支持多音频流**：修改 `remux` 逻辑，支持将输入文件中的所有音频流都拷贝到输出。

## 面试延伸题
- **问**：在一个复杂的转码管道中，如果其中一个环节（比如滤镜）出现了延迟，你会如何设计你的系统来保证整体吞吐量？
- **答**：可以引入多线程架构。为解码、滤镜、编码分别分配线程，并使用线程安全的队列进行数据传递。同时需要设置合理的队列深度阈值，防止内存溢出。
