# 第17节：转封装、流拷贝与精确剪辑

## 本节能力目标
- 理解 **Stream Copy** (流拷贝) 的原理及其在处理速度和画质上的优势。
- 掌握 FFmpeg 的 **Seek** 机制，区分“关键帧定位”与“精确时间定位”。
- 能够使用 C++ 实现不经过解码的高速剪辑（秒开剪辑）。
- 能够使用 C++ 实现经过解码的精确剪辑（解决剪辑点非关键帧的问题）。

## 真实工程对应场景
- **云端剪辑/短视频处理**：对于简单的视频截取，优先使用流拷贝以节省 CPU 资源并保持画质。
- **播放器 Seek**：用户拖动进度条时，播放器如何快速定位到目标位置并开始渲染。
- **高精剪辑工具**：如 Premiere、剪映等工具在导出时，如何确保导出片段的首帧严格符合用户设定的时间点。

## 引言
在前面的课程中，我们学习了如何解码和编码。但在实际工程中，并不是所有的操作都需要重编码。比如，如果你只是想把一个 10 分钟视频的中间 1 分钟截取出来，如果这一分钟恰好是从关键帧开始的，你完全可以直接把这些经过压缩的包（Packet）拷贝到新文件中，这个过程就是 **Stream Copy**。

本节课将深入探讨如何利用 FFmpeg API 进行高效的流拷贝剪辑，以及当剪辑点不是关键帧时，如何通过“解码+Seek”实现毫秒级的精确剪辑。

## 理论讲解

### 核心概念1：Stream Copy (流拷贝)
Stream Copy 是 FFmpeg 的一种工作模式，它跳过了解码（Decoding）和编码（Encoding）阶段。它只是简单地将原始码流从一个容器提取出来并封装到另一个容器中。
- **优点**：极快（受限于 I/O 速度）、画质零损耗。
- **局限性**：由于没有解码，你无法对画面进行修改（如加水印）；剪辑点必须是关键帧（I 帧），否则新生成的视频开头会出现花屏，直到遇到第一个关键帧。

### 核心概念2：FFmpeg Seek 机制
FFmpeg 提供了两个主要的 Seek 函数：
1. `av_seek_frame`：较老，通常用于基于帧索引或简单时间戳的定位。
2. `avformat_seek_file`：推荐使用。它允许你设置一个时间范围（min_ts, target_ts, max_ts），更加灵活。

**关键参数：`AVSEEK_FLAG_BACKWARD`**
当你请求定位到某个时间点时，FFmpeg 默认可能定位到该点之后的第一个关键帧。使用 `AVSEEK_FLAG_BACKWARD` 会让它定位到该点**之前**的最近一个关键帧。这在精确剪辑中至关重要：我们需要先回到之前的关键帧，然后解码并丢弃不需要的帧，直到达到精确的目标时间点。

### 核心概念3：精确剪辑 (Precise Clipping)
如果用户要求从 00:01:05.500 开始剪辑，而最近的前一个关键帧在 00:01:02.000。
1. **流拷贝做法**：只能从 00:01:02.000 开始，或者从 00:01:05.500 后的关键帧开始。
2. **精确做法**：
   - Seek 到 00:01:02.000 (关键帧)。
   - 启动解码器。
   - 解码并丢弃 [01:02.000, 01:05.500) 之间的所有视频帧。
   - 从 01:05.500 对应的 Frame 开始进行重编码或处理。

### 核心概念4：Timestamp Shifting (时间戳偏移)
在使用 Stream Copy 进行剪辑时，如果你从视频中间（例如第 10 秒）开始截取，截取出来的第一个 Packet 的 PTS 仍然是 10 秒。
- **问题**：某些播放器在播放这种视频时，进度条会直接跳到 10 秒，或者由于找不到 0 秒的帧而导致开头黑屏。
- **解决方法**：在写入 Packet 之前，减去起始点的偏移量，使输出文件的 PTS 从 0 开始。在本节的实验代码中，为了保持简单，我们展示的是原始时间戳的拷贝，但在实际工程中，通常需要进行 `pts -= start_pts` 的操作。

## 关键点总结
- **秒开剪辑**：依赖 `Stream Copy`，必须从关键帧开始。
- **精准剪辑**：必须涉及“解码 -> 寻找目标时间 -> 重编码”的流程。
- **Seek 策略**：总是 Seek 到目标点之前的关键帧，以保证解码器有完整的参考信息（GOP）。

## 预期结果与验收标准

### 预期输出
1. 使用 `fast` 模式剪辑 3.5s 处的视频，输出文件可能从 0s 开始（如果 GOP=5s），因为 3.5s 之前最近的关键帧在 0s。
2. 使用 `precise` 模式，输出的第一帧画面严格对应 3.5s 处的图像。

### 验收标准
- 程序在不同模式下均能正常运行。
- `fast` 模式下不进行任何解码操作（CPU 占用极低）。
- `precise` 模式下输出画面精准。
- 无内存泄漏（通过 ASAN 验证）。

## 常见错误与排查
- **剪辑后视频首帧绿屏/花屏**：通常是 `fast` 模式下没有从关键帧开始拷贝，或者拷贝了非 IDR 帧作为开头。
- **时间戳不连续**：在 `stream copy` 时，需要根据输出流的 `time_base` 重新计算 `packet->pts/dts`。
- **Seek 失败**：部分封装格式（如纯 H.264 裸流）没有索引，Seek 操作可能非常缓慢或失败。

## 面试延伸题
- **问**：为什么 `ffmpeg -ss 00:01:00 -i in.mp4 -c copy out.mp4` 有时候出来的视频开头会卡住几秒？
- **答**：因为 `-ss` 放在 `-i` 前面是快速定位，它会 Seek 到最近的关键帧。如果使用了 `-c copy`，FFmpeg 为了保证兼容性，会保留从关键帧到目标时间点之间的所有数据包，但设置了丢弃标记。某些播放器处理不当就会导致开头卡顿或黑屏。
